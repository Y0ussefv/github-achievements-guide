# 💬 GitHub Discussions — answers that get accepted

[GitHub Discussions](https://docs.github.com/en/discussions/quickstart) is a forum
built into repositories and organisations. Accepted answers count toward **Galaxy Brain**.

## How answers are accepted

- Only categories with the answer format (such as **Q&A**) support marking an answer.
- The person who opened the discussion — or a maintainer — clicks **Mark as answer**.

Docs: [Participating in a discussion](https://docs.github.com/en/discussions/collaborating-with-your-community-using-discussions/participating-in-a-discussion)

## Where to help

- [GitHub Community discussions](https://github.com/orgs/community/discussions)
- The **Discussions** tab of frameworks and tools you know well

## Anatomy of a great answer

1. **Confirm the problem.** “It sounds like X happens when Y.”
2. **Give the fix first**, with a minimal code sample.
3. **Explain why** it works.
4. **Link the docs.**
5. **Offer a next step** if it doesn't work.

## Templates

```markdown
This happens because <cause>.

Try:

    <command or code>

Why it works: <one or two sentences>.

Docs: <link>

If that doesn't help, could you share the output of `<diagnostic command>`?
```

## Tips

- Answer questions you can reproduce or have solved before.
- Test your code before posting.
- Be kind to beginners.
- If someone else answered first and correctly, upvote instead of duplicating.

## Don'ts

- Don't coordinate with friends to ask-and-answer for badges.
- Don't paste unverified AI output.
- Don't advertise your own projects in answers unless directly relevant.
